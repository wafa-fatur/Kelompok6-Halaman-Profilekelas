   # MEMAHAMI ISSUE
### 1. Apa fungsi GitHub Issue?
GitHub Issue berfungsi untuk mencatat tugas, masalah, atau pekerjaan yang harus dikerjakan dalam sebuah project.
### 2. Mengapa pekerjaan sebaiknya dicatat sebagai Issue?
Agar pekerjaan lebih teratur, mudah dibagi kepada anggota tim, dan dapat dipantau sampai selesai.
### 3. Apa perbedaan Issue dengan Commit?
* **Issue** = mencatat tugas atau masalah yang harus dikerjakan.
* **Commit** = menyimpan perubahan kode atau file ke dalam Git.

# SIMULASI MASALAH
### Kasus 1
**Andi dan Budi sama-sama mengerjakan halaman Profil. Apa yang seharusnya dilakukan?**
**Jawaban:**
Sebaiknya dibagi tugas atau menggunakan **branch yang berbeda** agar tidak terjadi konflik.
### Kasus 2
**Satu Issue sudah dikerjakan tetapi belum ada Pull Request. Apakah Issue sebaiknya langsung dianggap selesai? Mengapa?**
**Jawaban:**
Tidak. Sebaiknya menunggu **Pull Request diperiksa dan di-merge** terlebih dahulu agar perubahan sudah benar-benar masuk ke branch utama.
### Kasus 3
**Budi memiliki 20 commit, sedangkan Andi hanya 5 commit. Apakah otomatis Budi memiliki kontribusi lebih besar? Jelaskan.**
**Jawaban:**
Tidak otomatis. Jumlah commit bukan satu-satunya ukuran kontribusi. Yang penting adalah **isi, manfaat, dan kualitas perubahan** yang dikerjakan.
### Kasus 4
**Seseorang melakukan banyak commit tetapi sebagian besar hanya mengubah spasi atau format kode. Bagaimana cara menilai kontribusinya?**
**Jawaban:**
Dilihat dari **dampak dan isi perubahan**, bukan hanya jumlah commit. Perubahan yang hanya mengubah spasi atau format tidak berarti kontribusinya lebih besar.

# REFLEKSI TIM
### Sebelum menggunakan GitHub Issues:
Pekerjaan belum terlalu teratur dan sulit mengetahui tugas masing-masing anggota.
### Setelah menggunakan GitHub Issues:
Tugas menjadi lebih jelas, teratur, dan mudah dipantau.
### Hal yang paling membantu:
Pembagian tugas dan pemantauan progress pekerjaan.
### Hal yang masih membingungkan:
Cara menghubungkan Issue dengan Branch dan Pull Request.
### Perbaikan workflow tim:
Setiap tugas dibuat sebagai Issue, dikerjakan menggunakan Branch, kemudian dibuat Pull Request untuk diperiksa dan di-merge.
